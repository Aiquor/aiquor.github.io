## The workflow

A new inquiry reaches one agreed Gmail support mailbox. The workflow checks one client-approved FAQ document, applies a category label, and creates a reply draft when the answer is supported by that document. A team member reviews the draft, edits it if needed, and clicks Gmail’s Send button.

Messages that need account-specific information, an exception, or an unsupported answer receive a **Needs human review** label. The workflow does not send replies automatically.

### Three included categories

| Category | Included examples | Escalate to the team |
| --- | --- | --- |
| Product FAQs | Published dimensions, materials, care instructions, and general product information | Stock availability, suitability claims not covered by the FAQ, personalized advice |
| Shipping policy | Published shipping regions, standard delivery windows, and shipping charges | Where a specific order is, tracking updates, delivery guarantees, lost parcels |
| Returns policy | Published return window, eligibility rules, and instructions for requesting a return | Approving a return, issuing a refund, policy exceptions, disputes |

Each supported answer must come from the approved FAQ. An email can be assigned a category and still be escalated if it requires a human decision. Multi-topic, non-English, attachment-dependent, or unclear inquiries are escalated during this pilot.

## What you receive

1. **One Gmail connection:** a client-authorized connection to one support mailbox, processing new inquiries under an agreed label. Existing mailbox history is excluded from automated processing.
2. **One knowledge source:** one English FAQ document, up to 20 pages or 10,000 words, whichever limit is reached first. The client supplies and approves the content; Aiquor prepares it for the workflow. One consolidated content revision is included.
3. **Triage and drafts:** three category labels, a human-review label, and reply drafts for supported inquiries. Existing human drafts are not overwritten, and the same message is not processed twice.
4. **Failure handling:** failed runs are logged and surfaced for review. A failed or uncertain run cannot trigger an automatic reply.
5. **A pilot activity log:** message reference, processing time, assigned category, draft/escalation result, and errors. Credentials are never logged; raw message bodies are excluded from the activity log by default.
6. **Validation:** an acceptance report using the agreed 50-inquiry evaluation set, plus a measured comparison of manual drafting and assisted drafting time.
7. **Handover:** custom source code or workflow configuration, setup and operating instructions, a disconnect procedure, and one 45-minute walkthrough.
8. **Delivery coordination:** scope, progress, files, and acceptance feedback organized through ClientDesk by Aiquor. Customer support inquiries remain in Gmail.
9. **A defect-correction window:** seven calendar days after handover to report defects against the accepted scope. Feature requests and ongoing operation are separate work.

The included deployment is one agreed client-owned hosting or automation environment. Aiquor confirms compatibility during discovery before taking the deposit. Hosting subscriptions, cloud-account setup beyond the agreed environment, and ongoing administration are excluded.

## Acceptance criteria

The client approves a fixed evaluation set before testing: **35 in-scope inquiries and 15 inquiries that must be escalated**. These 50 inquiries are held out from tuning. A separate small sample is used during development. Aiquor records the initial results and any corrections; test cases are not silently removed or rewritten to improve the score.

| Check | Required result |
| --- | --- |
| Routing | At least 45 of 50 inquiries receive the agreed category or escalation outcome |
| Draft usefulness | At least 28 of the 35 in-scope inquiries produce drafts the reviewer accepts without substantive factual or policy changes; missing drafts count as failures |
| Mandatory escalation | All 15 designated escalation inquiries are sent for human review; none receive an unsupported customer-facing draft |
| Factual support | No evaluated draft invents an order status, refund approval, delivery guarantee, or policy absent from the approved source |
| Human control | No workflow-generated message is sent automatically; the reviewer must click Send in Gmail |
| Duplicate protection | Re-running an already processed message creates no extra draft; an existing human draft is preserved |
| Failure handling | Simulated provider and knowledge-source failures produce a reviewable error and no sent message |
| Handover | The client receives the agreed source/configuration, instructions, report, and walkthrough |

The source is a reference for answers, not an instruction channel. Checks also include messages that try to override the workflow’s rules; these must not cause automatic sending or disclosure of unrelated content.

Targets are agreed acceptance criteria, not claims of performance already achieved. If a check fails, Aiquor corrects the in-scope issue and repeats the affected checks before requesting final payment. Any change to scope or targets requires written agreement.

### Measuring time saved

The client reviewer times a matched sample of at least 10 in-scope inquiries: first the normal manual process, then reviewing an assisted draft. The report records median handling time for each method, the difference, and the number of drafts requiring substantive edits. Where practical, alternate which method is tested first to reduce familiarity effects. Results are directional pilot observations; a time-saving percentage is not a contractual guarantee.

## Boundaries

This pilot excludes live store/order integrations, refunds, cancellations, order edits, attachment processing, historical inbox cleanup, multiple inboxes, non-English support, automatic sending, 24/7 monitoring, and ongoing maintenance. No live order information is inferred from the FAQ. If these capabilities are needed, they are scoped and priced separately.

Before production access, the client approves the data processed and the AI provider used. Evaluation inquiries should be anonymized. Mailbox access uses client-authorized connections, with a documented way to revoke access; the client does not share their password with Aiquor. Retention and cleanup of evaluation data are agreed during kickoff.
